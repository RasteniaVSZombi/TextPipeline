# TextPipeline

## Описание

**TextPipeline** --- настольное WPF-приложение для обработки текстовых
данных с использованием контрактного подхода.

Проект разработан в рамках лабораторной работы №1 «Контракты в интерфейсе» и
лабораторной работы №2 «Движок слабейшего предусловия (wp) для последовательности и if»
по дисциплине «Теоретическая информатика».

Основная идея приложения заключается в том, что для каждой операции явно
задаются:

-   предусловие (**Pre**) --- требования к исходным данным;
-   постусловие (**Post**) --- свойства результата после выполнения
    операции;
-   эффекты и исключения;
-   валидный и невалидный примеры.

Состояние предусловия и постусловия отображается непосредственно в
пользовательском интерфейсе.

## Цель проекта

Продемонстрировать применение контрактного подхода при разработке
программного обеспечения:

-   формулирование предусловий и постусловий;
-   проверку предусловий перед выполнением операций;
-   контроль свойств результата после выполнения;
-   отображение состояния контрактов в графическом интерфейсе;
-   тестирование корректных и граничных сценариев.

## Технологии

-   **C# 12.0**
-   **.NET 8.0**
-   **WPF**
-   **MVVM**
-   **xUnit**
-   `Debug.Assert`
-   `Guard` для проверки предусловий

## Предметная область

Предметная область проекта --- обработка строк. Выбран сюжет «Текстовый
конвейер», в котором над входной строкой выполняются независимые
операции:

1.  нормализация текста;
2.  фильтрация символов;
3.  применение маски-шаблона.

# Реализованные операции

## 1. Нормализация текста

Операция приводит исходную строку к единому виду.

### Алгоритм

1.  Удаляются пробелы и другие пробельные символы в начале и конце
    строки.
2.  Последовательности пробельных символов заменяются одним пробелом.
3.  Текст переводится в нижний регистр.

### Контракт

**Pre:**

-   входная строка не должна иметь значение `null`.

**Post:**

-   отсутствуют пробелы в начале и конце;
-   отсутствуют последовательности повторяющихся пробелов;
-   текст приведён к нижнему регистру.

### Пример

``` text
Вход:
Hello    WORLD   Test

Результат:
hello world test
```

При нарушении предусловия `null` операция не выполняется и формируется
`ArgumentNullException`.

------------------------------------------------------------------------

## 2. Фильтрация текста

Операция позволяет оставить в строке только выбранные категории
символов.

Доступные категории:

-   буквы;
-   цифры;
-   прочие символы.

Выбор категорий реализован с помощью флагового перечисления
`CharacterType`.

### Контракт

**Pre:**

-   входная строка не должна иметь значение `null`;
-   должен быть выбран хотя бы один тип символов.

**Post:**

-   каждый символ результата соответствует выбранной категории.

### Пример

``` text
Вход:
Hello123!@

Выбрано:
Цифры

Результат:
123
```

------------------------------------------------------------------------

## 3. Применение маски

Операция формирует строку в соответствии с заданной маской.

Символ `#` используется как позиция для последовательной подстановки
символов входной строки. Остальные символы маски сохраняются.

### Контракт

**Pre:**

-   входная строка не должна иметь значение `null`;
-   маска не должна иметь значение `null`;
-   маска должна содержать хотя бы один символ `#`;
-   во входной строке должно быть достаточно символов для заполнения
    маски.

**Post:**

-   все позиции `#` заполнены;
-   остальные символы маски сохранены;
-   результат соответствует заданному формату.

### Пример

``` text
Вход:
1234567890

Маска:
+7 (###) ###-##-##

Результат:
+7 (123) 456-78-90
```

### Проверка нарушения предусловия

Для маски `+7 (###) ###-##-##` при вводе только `123` недостаточно
символов для заполнения всех позиций `#`. В интерфейсе предусловие
отображается как невыполненное.

# Контракты операций

## Структура контракта

Для каждой операции предусмотрен отдельный контракт.

Контракт содержит:

-   название операции;
-   предусловие (Pre);
-   постусловие (Post);
-   эффекты;
-   исключения;
-   валидный пример;
-   невалидный пример.

## Файлы контрактов

**Domain слой:**
* `Contracts.cs` — базовый класс контракта
* `OperationContract.cs` — описание структуры контракта
* `Guards.cs` — проверки предусловий

**UI слой:**
* `ContractWindow.xaml` — окно просмотра полного описания выбранного контракта
* `ViewModels` — логика отображения контракта

В главном окне приложения состояние предусловия и постусловия
отображается с помощью визуальных индикаторов.

------------------------------------------------------------------------

### Архитектура проекта

Приложение построено по архитектурному шаблону **MVVM (Model–View–ViewModel)**. Архитектура разделяет пользовательский интерфейс, управление состоянием и предметную логику.

Проект состоит из трёх основных частей:

- **TextPipeline** — WPF-приложение, отвечающее за пользовательский интерфейс и ViewModel;
- **Domain** — предметная область, содержащая операции обработки текста, контракты и проверки предусловий; содержит ядро вычислений wp;
- **Tests** — отдельный проект автоматизированного тестирования.

### View

Пользовательский интерфейс реализован средствами WPF/XAML.

Основные окна:

- `MainWindow.xaml` — главное окно приложения;
- `ContractWindow.xaml` — окно полного описания контракта.

### ViewModel

Для взаимодействия интерфейса с предметной логикой используется набор ViewModel:

- `MainViewModel` — управление доступными операциями и текущим состоянием интерфейса;
- `OperationViewModelBase` — общая функциональность операций;
- `NormalizeViewModel` — нормализация;
- `FilterViewModel` — фильтрация;
- `MaskViewModel` — применение маски.
- `WpViewModel` — конструктор фрагментов (составление wp).

`ObservableObject` используется для уведомления интерфейса об изменениях свойств, `RelayCommand` — для реализации команд. `BoolToColorConverter` и `BoolToTextConverter` преобразуют состояние контрактов в визуальное представление.

### Domain

Проект `Domain` содержит предметную логику:

**Контракты операций:**

- `TextOperations.cs` — методы `Normalize`, `FilterByCharType` и `ApplyMask`;
- `Contracts.cs` — описание `OperationContract` и контрактов операций;
- `Guard.cs` — проверка предусловий.
- 

**Модуль парсинга:**

- `Parser.cs` — точка входа для парсинга входных данных. Делегирует задачи специализированным парсерам для выражений и операторов.
- `ExpressionParser.cs` — парсит математические и логические выражения (переменные, операции, функции) в узлы дерева выражений.
- `ExpressionTypeChecker.cs` — выполняет статическую проверку типов в выражениях (например, запрещает сложение строки и числа, проверяет совместимость типов в условиях).
- `ExpressionSimplifier.cs` — оптимизирует дерево выражений: удаляет избыточные скобки, вычисляет константные подвыражения, нормализует логические операции.

**Модуль ядра вычислений:**

- `PredicateTransformer.cs` — реализует правила подстановки для оператора присваивания (`wp(x := E, R) = R[E/x]`) и сбор условий определённости (например, `b != 0` для деления).
- `WpCalculator.cs` — центральный класс движка. Управляет рекурсивным обходом AST, применяя правила wp для последовательностей (обратный проход) и ветвлений (`if-else`). Формирует пошаговый трейс преобразований.
- `ProgramAnalyzer.cs` — анализирует структуру программы до начала вычислений: подсчитывает количество операторов, ветвлений, собирает список уникальных переменных, проверяет наличие циклов (которые не поддерживаются в данной версии).
- `WpEngineService.cs` — сервисный слой, связывающий низкоуровневый калькулятор с ViewModel. Предоставляет удобные методы для получения статистики и готовых результатов.
- `ExamplePrograms.cs` — фабрика встроенных пресетов сценариев (максимум двух чисел, квадратное уравнение и др.) для демонстрации работы движка.

**Модуль моделей данных:**

- `Statement.cs` — базовый класс для представления операторов программы (присваивание, последовательность, условие).
- `WpExample.cs` — модель встроенного примера, содержащая код программы, постусловие и его описание.
- `WpResult.cs` — итоговый результат работы движка: слабейшее предусловие, условия определённости и финальная триада Хоара.
- `WpExecutionResult.cs` — расширенный результат, включающий подробный лог шагов преобразования (trace) для отображения в интерфейсе.

После выполнения операций свойства результата дополнительно контролируются с помощью `Debug.Assert`.

### Взаимодействие компонентов

Работа приложения с операциями строится следующим образом:

1. пользователь взаимодействует с `MainWindow`;
2. выбранная операция представляется соответствующей ViewModel;
3. ViewModel получает введённые данные;
4. ViewModel вызывает метод `TextOperations`;
5. `Guard` проверяет предусловия;
6. выполняется обработка текста;
7. контролируются свойства результата;
8. результат и состояние контракта отображаются в интерфейсе;
9. `ContractWindow` позволяет посмотреть полное описание контракта.


Работа приложения по вычислению слабейшего предусловия (wp) происходит по следующему алгоритму:

1. Пользователь открывает вкладку «Конструктор фрагментов» в `MainWindow` и вводит код программы и постусловие в редактор.
2. `WpViewModel` получает введенные строки и инициирует команду «Рассчитать wp».
3. `WpViewModel` вызывает сервис `WpEngineService` из проекта `Domain`.
4. `Parser.cs` преобразует строковый код программы и постусловия в абстрактное синтаксическое дерево (AST).
5. `ExpressionTypeChecker.cs` выполняет проверку типов и семантическую валидацию выражений.
6. `ProgramAnalyzer.cs` проводит предварительный анализ структуры программы (поиск циклов, сбор переменных).
7. `WpCalculator.cs` запускает рекурсивный процесс вычисления слабейшего предусловия, применяя правила трансформации предикатов через `PredicateTransformer.cs`.
8. `ExpressionSimplifier.cs` оптимизирует итоговое логическое выражение, убирая избыточность.
9. `WpEngineService` формирует объекты `WpResult` и `WpExecutionResult`, содержащие итоговое предусловие, условия определённости и лог шагов.
10. Результаты передаются обратно в `WpViewModel` и отображаются в панели результатов конструктора (слабейшее предусловие, триада Хоара, шаги преобразования).

Проект `Tests` используется для автоматизированной проверки операций и предусмотренных сценариев.

# Работа с конструктором фрагментов

## Ввод программы

**Конструктор фрагментов** предоставляет следующие возможности:

* **Редактор кода** для ввода программного фрагмента
* **Поле постусловия** для задания конечного условия
* **Выпадающий список** готовых примеров для быстрого старта

## Основные элементы интерфейса

### Панель ввода

* **Программа** — поле для написания кода
* **Постусловие** — условие, которое должно выполниться
* **Человекочитаемое описание** постусловия

### Панель результатов

* **Слабейшее предусловие** — итоговый результат вычислений
* **Шаги преобразования** — подробный лог вычислений
* **Условия определённости** — список ограничений
* **Триада Хоара** — формальное представление результата

## Анализ результатов

### Шаги вычисления

В разделе шагов отображаются:
* Последовательность преобразований
* Промежуточные результаты
* Применяемые правила
* Итоговые значения

### Триада Хоара

**Триада** формируется автоматически и содержит:
``` text
{Слабейшее предусловие} Программа {Постусловие}
```

# Пользовательский интерфейс

Для каждой операции пользователь видит:

-   поля ввода необходимых параметров;
-   кнопку **«Выполнить»**;
-   состояние предусловия;
-   состояние постусловия;
-   результат операции;
-   кнопку просмотра контракта.

Приложение позволяет непосредственно во время работы увидеть, выполнены
ли условия контракта.

Основные проверенные сценарии:

### Нормализация

``` text
Hello    WORLD   Test
        ↓
hello world test
```

Предусловие и постусловие выполнены.

### Фильтрация

``` text
Hello123!@
        ↓
     [Цифры]
        ↓
123
```

Предусловие и постусловие выполнены.

### Маска

``` text
1234567890
        ↓
+7 (###) ###-##-##
        ↓
+7 (123) 456-78-90
```

Предусловие и постусловие выполнены.

### Нарушение предусловия

``` text
Вход: 123
Маска: +7 (###) ###-##-##
```

Недостаточно символов для заполнения всех позиций `#`, поэтому
предусловие отображается как невыполненное.

# Конструктор фрагмента

Вкладка конструктора реализована как отдельный контент внутри `MainWindow`, интегрированный в общую навигацию приложения.

## Элементы управления

* Панель ввода кода: Многострочное текстовое поле. Поддерживает ввод операторов присваивания и условных конструкций.
* Поле постусловия: Текстовое поле для ввода логического выражения (например, `x > 0 && y < 10`).
* Панель инструментов:
    - Кнопка **«Рассчитать wp»**: Запускает процесс вычисления.
    - Кнопка **«Показать триаду»**: Отображает триаду Хоара
* Панель результатов:
    - Область вывода wp: Отображает итоговое слабейшее предусловие..
    - Область условий определённости: Выводит список дополнительных гарантий, необходимых для корректной работы программы.
    - Область триады Хоара: Форматированный вывод в виде `{Pre} Program {Post}`.
    - Область лога шагов: Промежуточные состояния трансформации предикатов.

Для проекта создан отдельный проект `Tests`.

-   `UITests` --- тесты, связанные с пользовательским интерфейсом.

В проекте предусмотрено **35 автоматизированных тестов** операций.

## Тестирование конструктора фрагмента

-   корректные сценарии;
-   `null`;
-   пустые входные данные;
-   отсутствие параметров;
-   корректность получаемого результата;
-   вычисление wp;
-   отображение результатов.

Классы тестов:

-   `WpCalculatorTests` — проверка корректности вычисления слабейшего предусловия и генерации условий определённости.
-   `WpEngineServiceTests` — интеграционные тесты сервисного слоя, проверяющие формирование итоговых результатов и обработку ошибок высокого уровня.
-   `PredicateTransformerTests` — валидация правил подстановки и трансформации предикатов.
-   `ProgramAnalyzerTests` — проверка анализа структуры программы, сбора переменных и детекции неподдерживаемых конструкций (циклов).
-   `ProgramParserTests` — тестирование парсинга программных фрагментов и обработки синтаксических ошибок.
-   `ExpressionParserTests` — проверка разбора арифметических и логических выражений, приоритетов операций и скобок.
-   `ExpressionTypeCheckerTests` — валидация семантической корректности выражений и выявление ошибок типизации.
-   `ExpressionSimplifierTests` — тестирование упрощения логических выражений и удаления избыточности.
-   `UITests` --- добавлены новые тесты, связанные с пользовательским интерфейсом.

В проекте предусмотрено **347 автоматизированных тестов** конструктора фрагмента, доводя общее количество тестов до **382 автоматизированных тестов**.


Запуск тестов выполняется через **Test Explorer** в Visual Studio.

-   для каждой операции определены предусловия и постусловия;
-   предусловия проверяются перед выполнением;
-   свойства результата контролируются после выполнения;
-   состояние контрактов отображается в пользовательском интерфейсе;
-   реализовано отдельное окно просмотра контракта;
-   реализован расчёт слабейшего предусловия из постусловия;
-   реализован показ триады Хоара на основе wp;
-   предметная логика отделена от интерфейса с помощью MVVM;
-   предусмотрены автоматизированные тесты.

Проект демонстрирует практическое применение контрактного подхода:
требования к входным данным и гарантии результата становятся явной
частью программной логики и отображаются пользователю.
